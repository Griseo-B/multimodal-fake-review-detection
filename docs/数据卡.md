读法：

- 只有 **餐饮** 同时有“真评实拍”和“为 AI 评论生成的 DALL·E 图”，是唯一能做真伪图像对照的领域。
- 电商、酒店的真评一侧几乎没有配对图，`text+mm` 只能落在 AI 一侧，那是来源线索，不是虚假线索。
- 人写假评的图是借用的网图（`shared_web` / `shared_entity`），不是伪造图；图像模态对它本身不含“假”的信号，详见 2.3。
- 有没有图和标签相关（真 23%、人假 76%、AI 假 75%），所以 **图本身不能当特征之外的第二条判据**，任何图像实验都要和“有没有图”这个基线对照。
- 「真评配自拍 + 假评配借用网图」的成品冻结在 `web_image_benchmark.csv`，见 2.4。

### 2.3 人写假评的配图：借用网图，三档对应强度

**设计前提**：现实中大量假评不是自己拍的，而是上网抓一张同一家店 / 同一款货的图贴上去。所以本数据集不把「假评没有原创图」当缺陷，而是按这个真实行为建模——**真评配自己的实拍，人写假评配借用网图**。口径写在 `code/data/build_web_image_benchmark.py` 的 docstring 里。

在这个前提下，「借用网图」还分三档对应强度，逐档核对过。核对脚本 `code/data/audit_image_assignment.py`（实体档）与 `code/data/repair_web_image_pairing.py`（品类档），结果在 `experiments/20261014_image_assignment/`、`experiments/20261019_web_image_pair/`。

| 档位 | 行数 | 唯一图 | 图的来源 | 对应关系 |
|---|---:|---:|---|---|
| `entity` 实体档 | 5,613 | 232 | 该酒店 / 该手机型号的图池，每个实体 3–8 张，中位 6 张 | 图就是评论写的那一家 |
| `category` 品类档 | 3,420 | — | 同菜系（12 类）或同品类（6 类）的实拍 | 图是同菜系 / 同品类，不是同一家 |
| `scene` 场景档 | 4,752 | — | 同场景（餐饮 / 酒店 / 电商）实拍 | 只保证大场景对得上 |

行数按 `image_role` 计，含真评那一侧；2.4 的基准表只取人写假那一侧，所以两处数字不同（`entity` 档在基准表里是 2,425 行）。

`entity` 档：可核对的 5,237 行里，分配实体与评论所写实体一致率 100%，文件名前缀与实体一致 100%。

`category` 档是本次新增的：`shared_web` 原来按 `domain` 全场景轮流发图，一条写火锅的假评可能配到咖啡馆的图。现在先从评论文本里判菜系 / 品类，再从**同品类**图池取图。判类器在 125 家自有店铺的真评上做过留出验证（`code/eval/category_matcher_validation.py`）：覆盖 51%，**精确率 0.963**，所以只把有把握的行升级到品类档，剩下 4,752 行老实留在场景档，不硬凑。

判类器保守到什么程度：需要同一类别命中 ≥2 个关键词，或者 1 个「店名 / 品名本身」的关键词（火锅店、咖啡馆、耳机）；同分平局直接放弃。

落表后再回查一遍：升级到品类档的 3,420 行，其图所在店铺 / 商品的实际菜系或品类与分配的 `category` **一致率 100%**（餐饮 2,500 行、电商 920 行各自 100%）——即配的图确实来自同菜系 / 同品类的实拍。

实体内真假共用同一图池，是为了让图不含标签信号：183 张图里 **100% 都被真假两类用过**（`web_image_pair_audit.json`）。核验（`code/eval/web_image_leakage.py`）：29 个实体内图 × 标签列联表置换检验统计量 5.62，零分布均值 156.0，p = 1.0；纯视觉 12 维的实体分组交叉验证 AUC 0.5414，接近 0.5。

### 2.4 借用网图基准表

`data/frozen/web_image_benchmark.csv`，**22,494 行，真 11,897 / 人写假 10,597**，是「真评配自拍 + 假评配网图」这一口径的冻结成品。

| 列 | 含义 |
|---|---|
| `pairing` | `own`（真评自拍）/ `entity` / `category` / `scene` |
| `binary_label` | 1 = 人写假 |
| `entity` / `category` | 借用图对应的实体 / 品类，`own` 行为空 |
| `split` | 按**图像身份**分组划分（实体档按实体、其余按图片文件），跨集合同图 0 张 |

基线（`code/eval/benchmark_baselines.py`，冻结划分）：纯文本 AUC 0.9934，纯视觉 0.8317，文本+全部图像 0.9937。图像相对纯文本的增量 +0.0003，即图像没有增量。

已知混杂，写在这里以免被当成结论：真评是业余随手拍、借用图是商家 / 网图精修，**低层图像统计本身就能分出两类**（纯视觉池化 AUC 0.832）。这是这条口径自带的，不是泄漏，但报数时必须同时给纯文本和纯图像两条线。

还有一个更硬的混杂：**真评一侧 85% 是英文**（AiGen 10,127 条），人写假一侧 73% 是中文（点评 7,692 条）。只看“文本是不是中文”这一个 bit，全表 AUC 0.7800，餐饮内部 0.9272。2026-11-01 补采把中文带图真评从 976 提到 1,770，语言捷径相应从 0.8209 / 0.9678 降下来，但**没有归零**，纯文本 0.9934 里有一部分仍然是语言差而不是虚假特征。

### 3.1 图片角色是标签的函数，不是标签的相关量

| 池 / image_role | 真 | 人假 | AI 假 |
|---|---|---|---|
| A / paired_sd | 0 | 0 | 1,319 |
| A / shared_entity | 796 | 1,120 | 0 |
| A / shared_web | 0 | 280 | 0 |
| B / paired_dalle | 0 | 0 | 10,001 |
| B / paired_review | 10,127 | 0 | 0 |
| B / paired_sd | 0 | 0 | 4,640 |
| B / shared_entity | 0 | 2,425 | 0 |
| B / shared_web | 0 | 480 | 0 |

两池都成立：`paired_dalle`、`paired_sd` 只出现在 AI 假，`paired_review` 只出现在真评，`shared_entity`、`shared_web` 只出现在人写假与真评。所以 **“图是不是生成的”等于“是不是 AI 假”，“图是不是共用”等于“是不是人写假”**。这不是可校正的偏差，是标签定义写进了图片角色。

自属图（`paired_*`）的逐标签覆盖：

| 池 / 标签 | 条数 | 有图 | 自属图 |
|---|---|---|---|
| A / real | 2,611 | 796 | 0 |
| A / human_fake | 1,920 | 1,400 | 0 |
| A / ai_fake | 2,637 | 1,319 | 1,319 |
| B / real | 19,891 | 10,127 | 10,127 |
| B / human_fake | 6,200 | 2,905 | 0 |
| B / ai_fake | 19,279 | 14,641 | 14,641 |

人写假评的自属图在两个池里都是 **0**。这不是采集疏漏：假评不会附一张能证明它在现场的照片。结论是三分类多模态在当前数据上组不出来；任何把共用图放进模型的写法都会把图片角色当标签用。实测见 `experiments/20261015_pool_multimodal/`：池 B 只用图像时人写假评 F1 = 1.000、AI 假 = 0.000。

中期口径据此锁定为「文本三分类 + 餐饮二分类图文真伪」：图像只在餐饮 20,128 行的真伪对照里用，三分类一律纯文本。范围这么写死的理由就是上两张表，不是模型还没调好。

| protocol | test | train | val |
|---|---|---|---|

文本侧干净：标准化后重复文本 0 条，跨 split 的 `group_id` 0 个。图像侧不干净：

- 全表 40,743 条带图样本里，共用图片 3,142 张；原始 `split` 下，测试集有 **917 行**的图片在训练集里出现过。
- 按图片 md5 归并后，池 A 有 1,690 行、池 B 有 2,242 行的图片被两个以上标签共用，这类图片在图像块实验里必须整组剔除。
- `split_purged` 把同一张图的全部行放在同一侧：池 A 的跨 split 图片行 27 → 0，池 B 152 → 0，全表 2,352 行换了划分。
- 目前唯一跑过的图像块（`public_dataset` 的 24,768 行）本来就没有重叠，所以那一组数字不受影响；受影响的是未来的酒店、电商图像实验。
